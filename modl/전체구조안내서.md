# 모들 전체 구조 안내서

모들(Modl)은 공동체를 운영하는 공간입니다. 첫 화면은 질문 창과 질문 목록입니다. 답은 목사가 씁니다. 교인, 출석, 주보, 재정, 승인은 분류 메뉴 안에 있습니다. 제주어는 공동체가 정한 메뉴 이름과 역할 이름에만 쓰고, 화면 문장은 표준어로 짧게 씁니다.  
지금 문서는 **7단계** 웹과, 그 화면을 감싸는 폰·패드·맥 앱을 설명합니다. 공동체, 가입, 교적, 모들 편성, 주일 기별(주보), 출석, 일정, 말씀 트멍(매일 묵상), 기도 수눌음(기도 나눔), 다정한 기별(기도 쪽지), 혼디 걸은 길(행사 기록)과 퀴즈, 공동체 살림(재정), 엑셀 내려받기, 설문, 회의록, 열린 안뜨레(외부 소개 홈페이지)까지 열었습니다. 그 다음 공동체 기능은 만들지 않았습니다. 화면은 Firebase App Hosting(파이어베이스 앱 호스팅, 서버를 항상 켜 두는 자리)에 올라가 있습니다. 자료는 이 컴퓨터의 127.0.0.1 이 아니라 파이어베이스 프로젝트 `modl-comm` 의 Postgres(포스트그레SQL, 표로 자료를 넣는 데이터베이스)에 있습니다.

이 폴더는 은혜로운 예배 저장소(소스 코드 저장소) 안에 따로 들어 있습니다. 예배 송출 앱과 파일을 섞지 않습니다. 아래 위치는 **모들 폴더**를 기준으로 합니다.

어려운 말은 괄호 안에 쉬운 뜻을 적었습니다.

## 1. 폴더가 하는 일

1. 화면 코드
   - `src/app` : 주소별 화면. 첫 화면의 질문, 질문 한 건, 지도, 계정, 공동체, 가입, 초대, 승인, 교적, 모들 편성, 주일 기별, 출석, 일정, 말씀, 기도, 기별, 행사 기록, 살림, 설문, 회의록, 엑셀과 영수증 받기, 홈페이지 편집, 공개 홈페이지.
   - `src/questions` : 질문이 누구에게 보이는지, 누가 답하고 승인하는지. 화면과 서버가 같이 씁니다.
   - `src/map` : 식당·숙소 구분, 길 응답, 제주 버스 응답과 노선 색, 제주도 기본 화면, 내 위치 반경, 따라가기 간격, 교회 엑셀 칸 이름을 읽는 규칙. 화면과 서버가 같이 씁니다. 없는 위치는 만들지 않습니다.
   - `src/moderation` : 금지어가 한 단어로 들어왔는지 가르는 규칙. 단어 목록은 이 폴더에 없습니다.
   - `src/bulletin` : 주보 블록(주보 안의 한 덩어리) 규칙. 화면과 서버가 같이 씁니다.
   - `src/attendance` : 출석 계산 규칙. 화면과 서버가 같이 씁니다.

기술 묶음은 이렇게 고정합니다.

1. Next.js (넥스트, 화면 주소를 만드는 틀) App Router + TypeScript (타입스크립트, 값의 종류를 미리 적는 자바스크립트) + React (리액트, 화면 조각)
2. Tailwind CSS (테일윈드, 화면 모양을 짧게 적는 도구)
3. PostgreSQL (포스트그레SQL, 표로 자료를 넣는 데이터베이스) + Drizzle ORM (드리즐, 표 모양을 코드로 적는 도구)
4. zod (조드, 들어온 값이 약속한 모양인지 검사하는 도구)
5. 패키지 매니저(꾸러미 설치 도구)는 이 저장소와 같이 npm 입니다.

메뉴 이름과 역할 이름은 테마 엔진(이름을 고르는 장치)을 통과합니다. 설명 문장은 표준어입니다. 이름 옆에 긴 풀이를 붙이지 않습니다.

## 2. 자료는 어디에 들어가나

자료 창고는 PostgreSQL 입니다. 공개 앱은 파이어베이스 프로젝트 `modl-comm` 의 Postgres를 씁니다. 이 컴퓨터의 `127.0.0.1` 은 공개 앱이 쓰지 않습니다.  
파이어베이스는 화면을 올려 두는 앱 호스팅으로 연결했습니다. Firestore(파이어스토어, 문서 묶음 자료 창고) 묶음은 만들지 않았습니다.  
나중에 파이어베이스 자료 묶음을 만들면 이름 맨 앞에 반드시 `[모들]_` 를 붙입니다.

1. 예: `[모들]_회원목록`
2. 이번에도 그 묶음은 만들지 않습니다.

표를 만드는 명령은 `src/server/db/migrations/0001_init.sql` 입니다.  
같은 모양이 코드로는 `src/server/db/schema.ts` 에 있습니다.  
코드를 불러도 바로 접속하지 않습니다. 화면이 자료를 읽을 때 `ensureDatabase()` 가 접속하고, 없는 표만 만듭니다. 이 컴퓨터에서는 `.env` 의 `DATABASE_URL` 을 쓰고, 공개 앱은 그 주소 대신 프로젝트 Postgres 환경 변수를 씁니다.

### 2.1 왜 추가 표가 있나

요청서의 업무 표 외에, 로그인과 가입을 위해 표를 더 두었습니다.

1. `users` : 앱 로그인 계정. 이메일, 비밀번호 해시(원문 비밀번호를 한 방향으로 바꾼 값), 전화번호, 성별, 다니는 교회를 둡니다. 전화번호와 교회는 비밀 열쇠가 아닙니다.
2. `sessions` : 로그인 상태를 서버가 기억합니다. 표식 원문은 저장하지 않고 해시만 둡니다.
3. `invite_codes` : 어느 공동체로 들어오라는 초대 코드입니다.
4. `approval_requests` : 가입 승인 대기열입니다. 교단 확인 여부, 상태 `PENDING|APPROVED|REJECTED`, 연결할 `member_id`(비어 있을 수 있음)를 둡니다. 이미 있는 미가입 명부와 합칠 때 그 칸을 씁니다.
5. `group_memberships` : 누가 어느 해의 어느 모들에 있었는지 남기는 연결 기록입니다. 해가 바뀌거나 사람을 옮겨도 줄을 지우지 않고, 끝난 줄만 `ended_at` 을 채웁니다. 한 사람의 진행 중 연결은 하나만 둡니다.
6. `oauth_identities` : 카카오 또는 네이버로 들어온 계정의 연결입니다. 제공자 이름과 그 쪽 회원 번호만 둡니다. 열쇠 값은 두지 않습니다. 표 만들기 명령은 `src/server/db/migrations/0016_oauth_identities.sql` 입니다.
7. `users.phone`, `users.gender` : 계정을 만들 때 받는 전화번호와 성별입니다. 비밀 열쇠가 아니고, 코드에 번호를 적지 않습니다. 성별은 `male`(남) 또는 `female`(여)입니다. 예전 계정은 비어 있을 수 있습니다. 명령은 `src/server/db/migrations/0017_user_phone_gender.sql` 입니다.
8. `oauth_pending` : 카카오·네이버가 성별이나 전화번호를 주지 않으면, 가입을 끝내지 않고 빠진 칸만 잠시 기억합니다. 계정을 만든 뒤 그 줄은 지웁니다.
9. `users.home_church_id` : 가입이 끝난 뒤 직접 등록한 다니는 교회입니다. 지도의 교회 줄을 가리킵니다. 비밀 열쇠가 아닙니다. 명령은 `src/server/db/migrations/0018_user_home_church.sql` 입니다.

### 2.2 공동체마다 자료를 가둡니다

거의 모든 업무 표에 `community_id` 가 있고, 그 칸으로 찾아보게 인덱스를 달았습니다.  
다른 공동체 번호로 들어온 요청은 권한 검사가 거절합니다.

모들 글, 사진첩, 출석 한 줄, 묵상 답, 기도 반응과 쪽지는 공동체 번호가 부모 표에 있습니다.

1. 글과 사진첩은 `group_id` → `small_groups.community_id`
2. 출석 한 줄은 `session_id` → `attendance_sessions.community_id`
3. 묵상 답은 `qt_id` → `daily_qts.community_id`
4. 기도 반응과 쪽지는 `prayer_request_id` → `prayer_requests.community_id`

이 줄을 열기 전에 부모의 공동체 번호를 확인하고 `assertCan` 에 넘깁니다.

### 2.3 표 목록

1. `communities` 공동체
   - 이름, 교회 이름, 교단, 주소 이름(`slug`, 서로 겹치면 안 됨)
   - 사용 등급 `plan_tier` : `FREE` 또는 `PRO`
   - 가입 승인이 필요한지 `require_approval`
   - 말투 `language_mode` : `JEJU_DUAL`, `JEJU_ONLY`, `STANDARD`
   - 말 덮어쓰기 `custom_term_overrides` (JSONB, 모양을 유연하게 담는 칸)
2. `users` 앱 계정. 이메일은 서로 겹치면 안 됩니다. 카카오·네이버로 들어온 연결은 `oauth_identities` 에 제공자 번호만 둡니다. 열쇠는 적지 않습니다.
3. `sessions` 로그인 표식 해시. 계정을 지우면 함께 지워집니다.
4. `members` 명부
   - `community_id` 로 공동체에 속합니다. 공동체를 지우면 명부도 지워집니다.
   - `user_id` 는 비울 수 있습니다. 비어 있으면 **미가입 명부**입니다. 역할 이름에 UNREGISTERED 는 없습니다.
   - 계정을 지워도 명부는 남고 `user_id` 만 비워집니다.
   - 역할 `role` : `PASTOR`, `EXECUTIVE`, `CELL_LEADER`, `MEMBER`, `NEWCOMER`
   - 구분 `cohort` : 비어 있거나 `PEER`(또래), `SENIOR`(선배). 질문이 보이는 범위를 고를 때 씁니다.
   - 상태 `status` : `ACTIVE`, `LONG_ABSENT`, `GRADUATED`
   - 화면에서 `LONG_ABSENT` 의 호칭은 **보고픈 괸당**입니다. 데이터베이스에는 영문 코드만 저장합니다.
   - 전화번호, 생일, 성별도 이 줄에 둡니다.
   - `current_group_id` 는 지금 속한 모들. 모들이 사라지면 칸만 비웁니다.
5. `invite_codes` 초대 코드. 코드는 서로 겹치면 안 됩니다.
6. `approval_requests` 가입 승인 대기열.
7. `small_groups` 계절 모들. `season_year` 가 해입니다. 해가 바뀌면 `is_archived` 만 참으로 바꾸고 줄은 남깁니다. 리더가 빠지면 리더 칸만 비웁니다.
8. `group_memberships` 모들 편성 기록. 표 만들기 명령은 `src/server/db/migrations/0002_group_memberships.sql` 입니다.
9. `group_posts` 모들 글. 모들이나 글쓴이가 지워지면 글도 지워집니다.
10. `group_albums` 모들 사진첩. 게시글과 따로 둡니다.
11. `bulletins` 주일 기별(주보). `share_token` 은 서로 겹치면 안 됩니다. 아직 공개 전이면 비울 수 있습니다. `service_label` 은 한 번에 읽은 예배 이름이고, `service_time` 은 그 예배 시각입니다.
12. `attendance_sessions` 출석 모임. 부서 `YOUTH` 또는 `SCHOOL`. QR 표식은 서로 겹치면 안 됩니다.
13. `attendance_records` 출석 한 줄.
    - 상태 `PRESENT`, `LATE`, `ABSENT`, `EXCUSED`
    - 확인 방법 `SELF_QR`, `GROUP_LEADER`, `EXECUTIVE`
    - 같은 모임과 같은 사람은 한 줄만 (`session_id` + `member_id` 유니크)
14. `calendar_events` 일정.
    - 분류 `RETREAT`, `EVENT`, `BIRTHDAY`, `HOLIDAY`, `ETC`
    - `is_leader_only` 가 참이면 리더 일정
    - `group_id` 가 비어 있으면 교회 일정이고, 있으면 그 모들 식구만 봅니다.
    - `bulletin_id` 가 있으면 주보를 읽어 만든 일정입니다. 주보를 지우면 그 일정도 지워집니다.
    - 끝나는 시각은 시작보다 빠를 수 없습니다.
15. `daily_qts` 하루 묵상 본문.
16. `qt_reflections` 개인 묵상.
17. `prayer_requests` 기도 나눔.
    - 공개 범위 `PUBLIC`, `GROUP_ONLY`, `LEADER_ONLY`, `PASTOR_ONLY`
    - `group_id` 는 비울 수 있습니다. 모들이 지워지면 칸만 비웁니다.
18. `prayer_reactions` 함께 기도한 기록. 같은 글과 같은 사람은 한 줄만.
19. `prayer_letters` 기도 쪽지.
20. `finance_categories` 살림 항목. 종류 `INCOME` 또는 `EXPENSE`.
21. `transactions` 돈 기록. 금액은 0보다 작을 수 없습니다. 적은 사람이 빠져도 기록은 남고 적은 사람 칸만 비웁니다. 항목을 지우면 그 항목의 기록도 함께 지워집니다.
22. `surveys` 설문. 제목, 질문 JSON(질문을 담은 자료 모양), `allow_anonymous`, 마감, 만든 사람 `created_by_member_id`.
23. `survey_responses` 설문 답. 익명이면 구성원 번호가 비어 있습니다. 표 만들기 명령은 `src/server/db/migrations/0004_survey_responses.sql` 입니다.
24. `meeting_minutes` 회의록. 날짜, 참석자, 본문, 첨부 주소.
25. `event_archives` 행사 기록과 영상 주소.
26. `quizzes` 퀴즈.
27. `website_configs` 열린 안뜨레 설정. 공동체마다 하나이고, 주소 이름은 서로 겹치면 안 됩니다. `theme_json` 은 글꼴·배경색·버튼 모양, `seo_json` 은 검색 제목·설명·대표 이미지·노출 여부, `blocks_json` 은 블록 목록, `visit_count` 는 방문 수입니다.
28. `website_inquiries` 방문 문의.
29. `questions` 질문. 본문, 지정한 목사(비울 수 있음), 보이는 범위 `PASTORS`(목사), `PEERS`(또래), `SENIORS`(선배). 표 만들기 명령은 `src/server/db/migrations/0005_questions.sql` 입니다.
30. `question_replies` 답글. 목사가 쓰고, 상태는 `PENDING`(승인 전) 또는 `APPROVED`(승인 후)입니다.
31. `banned_words` 금지어 표. 단어는 이 표에만 두고 코드에 고정하지 않습니다. 사용자 이름을 눌러 연 계정에서 사역자만 고칩니다. 표 만들기 명령은 `src/server/db/migrations/0007_banned_words.sql` 입니다.
32. `worship_caption_links` 예배 자막 링크. 교회마다 언어 하나씩, 주소는 https 만 둡니다. 비운 언어는 표에 넣지 않습니다. 표 만들기 명령은 `src/server/db/migrations/0014_worship_caption_links.sql` 입니다.

모든 표에는 만든 시각 `created_at` 과 고친 시각 `updated_at` 이 있습니다.  
명부에는 가입 시각 `joined_at`, 출석에는 확인 시각 `checked_at` 도 있습니다.

지우는 규칙의 뜻은 이렇습니다.

1. 공동체를 지우면 그 공동체 자료도 함께 지워집니다 (`ON DELETE CASCADE`, 부모를 지우면 자식도 지움).
2. 계정만 지우면 명부는 남습니다 (`ON DELETE SET NULL`, 가리키던 칸만 비움).
3. 모들을 지우면 그 모들의 글과 사진첩은 함께 지워집니다.
4. 출석 모임을 지우면 출석 기록도 함께 지워집니다.
5. 기도 글을 지우면 반응과 쪽지도 함께 지워집니다.
6. 화면에서 시즌을 바꿀 때는 모들 줄을 지우지 않습니다. 이전 해는 `is_archived` 만 참으로 둡니다.

손님(GUEST)은 로그인하지 않은 요청입니다. `members` 줄이 아닙니다. 첫 화면, 기도, 지도는 로그인 없이 열립니다. 출석, 주보, QT, 달력, 퀴즈, 재정, 회의록, 행사자료, 웹사이트는 로그인이 필요하고, 손님이 누르면 화면이 깨지지 않고 로그인 안내가 나옵니다.

## 4. 바깥 서비스와 비밀 이름

7단계에서 바깥에 꼭 연결하는 것은 데이터베이스입니다. 카카오톡 공유, 구글 달력, 사진 글 읽기, 구글 시트, 문의 푸시는 열쇠가 있을 때만 붙입니다.

1. `DATABASE_URL` : 이 컴퓨터에서만 쓰는 PostgreSQL 접속 주소. `modl/.env` 에만 적습니다. 공개 앱은 이 값을 쓰지 않습니다.
2. `CLOUD_SQL_CONNECTION_NAME` : 공개 앱이 붙는 `modl-comm` Postgres 인스턴스 이름. 비밀번호가 아닙니다.
3. `DB_USER` : 공개 앱의 데이터베이스 사용자 이름.
4. `DB_NAME` : 공개 앱의 데이터베이스 이름.
5. `DB_PASSWORD` : 공개 앱의 데이터베이스 비밀번호. 비밀 저장소 이름 `modl-db-password` 에만 있습니다. 코드, 이 안내서, 커밋, 풀 리퀘스트에 적지 않습니다.
6. `KAKAO_JAVASCRIPT_KEY` : 카카오톡 공유용 자바스크립트 열쇠. 비우면 공유 버튼은 링크 복사만 합니다.
7. `KAKAO_SHARE_TEMPLATE_ID` : 카카오 공유 꾸러미 번호. 숫자가 있을 때만 그 꾸러미를 씁니다. 없으면 공개 주소의 미리보기 카드를 씁니다.
8. `GOOGLE_CALENDAR_CLIENT_ID` : 구글 달력 클라이언트 번호.
9. `GOOGLE_CALENDAR_CLIENT_SECRET` : 구글 달력 클라이언트 비밀.
10. `GOOGLE_CALENDAR_REFRESH_TOKEN` : 구글 달력을 다시 열 때 쓰는 갱신 표식.
11. `GOOGLE_CALENDAR_ID` : 구글 달력 번호의 이름입니다. 값은 앱 호스팅 비밀 저장소에만 있습니다. 이 번호가 없으면 구글에 보내지 않고, 없는 일정은 만들지 않습니다.
12. `GOOGLE_CALENDAR_API_KEY` : 구글 달력 API 열쇠의 이름입니다. 값은 앱 호스팅 비밀 저장소에만 있습니다. 달력 번호가 있을 때만 그 열쇠로 구글 달력 API를 부릅니다. 예전 로그인 열쇠 네 개가 모두 있을 때도 보냅니다. 보낼 수 없으면 모들 달력만 쓰고, 보냈다고 말하지 않습니다.
13. `QT_OCR_API_KEY` : 말씀 사진과 주보 사진에서 글을 읽는 열쇠 이름. 값이 없으면 사람이 직접 적습니다. 주보 사진은 저장만 하고 칸은 비워 둡니다. 읽지 못한 글을 만든 것처럼 말하지 않습니다.
14. `GOOGLE_SHEETS_SERVICE_ACCOUNT` : 구글 시트에 들어가는 모들 전용 계정 열쇠의 이름입니다. 계정 메일(시트를 공유할 때 쓰는 주소)은 `modl-sheets@modl-comm.iam.gserviceaccount.com` 입니다. 열쇠 파일 내용과 개인 열쇠 글은 앱 호스팅(공개 앱을 올려 두는 곳) 비밀 저장소에만 있습니다.
15. `GOOGLE_SHEETS_SPREADSHEET_ID` : 연결된 시트 번호의 이름입니다. 번호 값은 같은 비밀 저장소에만 있고, 이 안내서에는 적지 않습니다.
16. 연결은 파이어베이스 프로젝트 `modl-comm` 에 있습니다. 시트 제목은 `modl_sheet` 이고, 탭(시트 안의 칸 묶음) 이름은 `시트1` 입니다. 칸 안의 이름, 연락처, 금액은 적지 않습니다.
17. 시트는 위 계정 메일에 편집자로 공유되어 있습니다. 프로젝트 전체를 고치는 권한은 주지 않았습니다.
18. 지금 연결에 쓰는 비밀 이름은 14번과 15번뿐입니다. 열쇠 본문과 시트 번호 값은 깃에 올리지 않습니다.
19. `INQUIRY_PUSH_KEY` : 방문 문의를 휴대폰 알림으로 보낼 때 쓰는 열쇠 이름. 값이 없으면 사역자와 임원 화면의 알림 목록만 갱신합니다. 보내지 못한 푸시를 보낸 것처럼 말하지 않습니다.
20. `APPLE_ID` : 애플 개발자 계정 이메일. 없으면 테스트플라이트에 올리지 않습니다.
21. `APPLE_TEAM_ID` : 애플 개발자 팀 번호. 앱 프로젝트에는 값 대신 이 이름만 연결합니다.
22. `MODL_BUNDLE_ID` : 앱 묶음 식별자(번들 아이디, 스토어에서 앱을 구분하는 이름). 값을 코드에 적지 않습니다.
23. `APP_STORE_CONNECT_API_KEY_ID` : 앱스토어 커넥트 열쇠 번호.
24. `APP_STORE_CONNECT_API_ISSUER_ID` : 그 열쇠를 만든 발행 번호.
25. `APP_STORE_CONNECT_API_KEY_PATH` : `.p8` 열쇠 파일의 경로. 파일 내용은 깃에 올리지 않습니다.
26. 위 애플 이름이 하나라도 없거나 이 컴퓨터에 Xcode 가 없으면 테스트플라이트에 올리지 않습니다. 올린 것처럼 말하지 않습니다.
27. 예시 파일 `modl/.env.example` 에는 이름과 빈 자리만 있습니다.
28. 지도 그림은 맵박스(Mapbox, 지도 그림을 빌려 주는 서비스)입니다. 비밀 이름은 `MAPBOX_ACCESS_TOKEN` 이고, 값은 앱 호스팅 비밀 저장소에만 있습니다. 코드, 안내서, 기록에는 값을 적지 않습니다. 지도를 그리는 화면 도구는 실행 중에 그 비밀을 읽어 브라우저로 넘깁니다. 넘기지 않으면 맵박스가 그림을 그리지 않습니다. 허용된 공개 주소는 `https://modl--modl-comm.asia-east1.hosted.app` 한 줄이며, 별표나 경로를 붙이지 않습니다. 지도 조각은 그 주소만 붙여 서버가 받아 옵니다. 자동차와 도보 길은 같은 비밀로 맵박스 길찾기를 부르며, 응답에 선이 없으면 그리지 않습니다. 기본 화면은 제주도 전체입니다. 내 위치가 있으면 그 점을 가운데 두고 반경 10km가 보이게 확대합니다. 따라가기는 실제 위치를 받아 그 점을 따라가며, 선을 따라 카메라가 날아가지 않습니다. 길에서 약 100m 벗어나면 같은 수단으로 다시 찾고, 화면에 "재탐색"이라고 짧게 보여 줍니다. 빨리 움직이면 넓게, 천천히 움직이면 지금 있는 곳이 크게 보입니다. 속도가 없으면 중간 간격만 씁니다. 식당·숙소 검색은 열쇠 없는 공개 서비스를 씁니다. 제주 버스는 정의서의 주소만 부릅니다. 정의서의 보안 항목은 열쇠 없음이라 버스 열쇠 이름은 두지 않습니다. 응답이 없으면 실패만 말하고, 없는 장소나 좌표를 만들지 않습니다.
29. 비밀번호, 열쇠, 서비스 계정 JSON 본문은 코드와 이 안내서에 적지 않습니다.
30. 글꼴은 비밀이 아닙니다. 제주특별자치도 서체 안내(https://www.jeju.go.kr/jeju/symbol/font/infor.htm)에서 받은 제주고딕, 제주명조 TTF 파일을 그대로 씁니다. 공공누리 제1유형이라 출처를 화면에 적고, 글꼴 파일은 팔지 않습니다. 로고 그림은 글꼴로 바꾸지 않습니다.
31. `GOOGLE_SQL_ADMIN_CREDENTIALS` : 버셀(Vercel, 공개 웹을 올려 두는 또 다른 곳)에서만 쓰는 구글 로그인 파일의 이름입니다. 버셀에는 구글 기본 로그인이 없어서, 데이터베이스 인증서를 받을 때만 이 이름을 읽습니다. 값은 버셀 비밀에만 있고, 코드와 이 안내서와 깃에는 적지 않습니다. 파이어베이스 앱 호스팅은 이 이름 없이 그대로 접속합니다.
32. `KAKAO_REST_API_KEY` : 카카오 로그인 REST API 열쇠. 값은 비워 둡니다. 없으면 카카오 로그인 버튼을 눌러도 들어가지 않고, 열쇠가 없다는 안내만 나옵니다.
33. `KAKAO_CLIENT_SECRET` : 카카오가 클라이언트 비밀을 켜 둔 경우에만 같이 보냅니다. 값은 비워 둡니다.
34. `NAVER_CLIENT_ID` : 네이버 로그인 클라이언트 아이디. 값은 비워 둡니다.
35. `NAVER_CLIENT_SECRET` : 네이버 로그인 클라이언트 비밀. 값은 비워 둡니다. 아이디와 비밀이 없으면 네이버 로그인 버튼을 눌러도 들어가지 않습니다.
36. 카카오에 등록할 리다이렉트 주소는 `https://modl-jeju.vercel.app/api/auth/callback/kakao` 입니다. 네이버에 등록할 콜백 주소는 `https://modl-jeju.vercel.app/api/auth/callback/naver` 입니다. 다른 콜백 경로는 만들지 않습니다. 카카오에는 전화번호와 성별 동의항목을 같이 요청합니다. 네이버 개발자 화면의 제공 정보에서는 휴대전화와 성별을 켜 둡니다. 그 값이 오면 계정에 저장하고, 없으면 가입을 끝내기 전에 빈 칸만 입력받습니다. 직접 가입도 성별(남/여)과 전화번호가 둘 다 있어야 계정이 만들어집니다. 로그인 화면에는 공동체 만들기와 사용 등급 고르기를 두지 않습니다. 가입이 끝나면 `/signup/church` 에서 교회이름·담임목사·주소·전화번호·주일 예배시간·메모와 네 묶음 필터로 다니는 교회를 등록합니다. 교회 목록과 이름 검색, 지역 필터, 등급 칸은 없습니다. 이미 교회를 정한 계정은 그 화면으로 다시 가지 않습니다.

깃 업로드 차단은 저장소 루트 `.gitignore` 와 `modl/.gitignore` 양쪽에 있습니다. 확인한 항목은 아래와 같습니다.

1. `.env`
2. `.env.*` (단, `.env.example` 은 예외로 올립니다)
3. `secrets/`
4. 열쇠 파일(`*.pem`, `*.key`)과 자격 증명 파일 이름

데이터베이스가 없어도 타입 검사와 단위 테스트는 돌아갑니다.

## 5. 권한 여섯 단계

권한은 서버 모듈 `src/server/auth` 에서만 판단합니다. 화면은 이 파일을 부르지 않습니다.  
핵심 함수는 `assertCan`(할 수 없으면 오류)과 `visiblePrayerFilter`(이 기도 글이 보이는지)입니다.

역할은 다섯 개이고, 손님까지 여섯 단계로 부릅니다.

1. `PASTOR` 큰 테우리
   - 그 공동체의 모든 일.
   - 사역자 전용 기도 `PASTOR_ONLY`, 말투, 사용 등급 `plan_tier`.
2. `EXECUTIVE` 살림꾼
   - 교적, 전체 출석 수정, 출석 통계, 보고픈 괸당, 재정, 설문·회의록, 홈페이지, 리더 일정, 질문 답글 승인. 주보 만들기와 자막 언어 연결은 하지 않습니다.
   - 교적에서 역할을 목사로 두고, 또래와 선배를 구분합니다.
   - 사역자 전용 기도는 볼 수 없습니다.
3. `CELL_LEADER` 모들 테우리
   - 출석은 자신이 맡은 모들 식구만 고칩니다. 다른 모들 식구는 출석 화면에서 고치지 못합니다.
   - 글과 사진은 자신이 리더인 모들, 또는 지금 속한 모들입니다.
   - 리더 전용 기도 `LEADER_ONLY` 는 그 모들만.
   - 리더 일정은 볼 수 있습니다.
4. `MEMBER` 괸당
   - 공개 주보, 본인 묵상, 공개 범위 안의 기도, 공개 일정, 본인 모들 페이지.
5. `NEWCOMER` 새 괸당
   - 구성원과 같은 범위입니다.
6. `GUEST` 마중 손님
   - 공개 주보의 나누기 표식 `share_token`
   - 열린 안뜨레
   - 방문 문의
   - `allow_anonymous` 가 켜진 설문만

가입 승인 요청이 `PENDING` 이면 `assertApprovedMember` 가 정식 구성원 권한을 주지 않습니다.  
그 사람은 그 공동체에서 손님처럼 열린 안뜨레와 익명 설문만 할 수 있습니다.

2단계에서 추가한 일은 이렇습니다.

1. `create_community`, `apply_to_join` : 로그인한 계정이면 할 수 있습니다.
2. `issue_invite`, `review_approval`, `manage_groups`, `manage_roster` : 그 공동체의 `PASTOR` 또는 `EXECUTIVE` 만 할 수 있습니다.
3. 승인 대기 중이면 이 일들도 할 수 없습니다.
4. 다른 공동체 자료는 목록에 나오지 않습니다. 서버가 지금 공동체의 줄만 읽고, 고친 줄도 `assertSameCommunity` 로 확인합니다.

다른 공동체 번호의 자료는 `assertSameCommunity` 와 소속 검사가 거절합니다.

기도 글을 거르는 규칙은 이렇습니다.

1. 작성자 본인은 공개 범위와 상관없이 자기 글을 봅니다. 승인 대기 중이어도 자기 글은 봅니다.
2. `PUBLIC` : 그 공동체의 정식 구성원.
3. `GROUP_ONLY` : 그 모들 식구, 그 모들 테우리, 사역자.
4. `LEADER_ONLY` : 그 모들 테우리, 사역자.
5. `PASTOR_ONLY` : 사역자.
6. 손님과 다른 공동체 사람은 기도 글을 보지 못합니다.
7. `is_anonymous` 가 참이면 `toPrayerDto` 가 작성자가 아닌 응답에서 작성자 번호를 뺍니다. 본인 응답에는 남깁니다.

1단계에서는 이 규칙을 함수와 테스트로만 두었습니다. 제품용 API(외부 연결 통로) 전체는 만들지 않았습니다.

## 6. 이름과 화면 문장

중점은 공동체 운영입니다. 언어는 이름만 정합니다.

1. 첫 화면은 질문 창과 질문 목록입니다. 교인, 출석, 주보, 재정, 승인, QT, 기도, 달력, 설문, 회의록, 웹사이트는 분류 메뉴에 있습니다. 말투 견본과 방언 설명은 두지 않습니다.
2. 설명, 버튼, 안내 문장은 표준어로 짧게 씁니다.
3. 제주어는 공동체가 정한 메뉴 이름과 역할 이름에만 씁니다. 이름 옆에 표준어 풀이나 긴 설명을 붙이지 않습니다.
4. 손님 화면의 메뉴 이름은 표준어입니다. 공동체에 들어가면 그 공동체의 `language_mode` 가 메뉴와 역할 이름만 바꿉니다.

이름 값은 세 가지입니다.

1. `JEJU_DUAL` : 제주어 이름. 화면에는 그 이름만 나옵니다.
2. `JEJU_ONLY` : 제주어 이름만.
3. `STANDARD` : 표준어 이름. 새로 만드는 공동체 폼의 기본값입니다.

화면에서는 `useCommunityTerm(키)` 가 `termForScreen` 으로 말을 고릅니다.  
서버의 `resolveTerm` 은 저장된 이름 규칙을 그대로 계산합니다.  
제목은 `TermHeading`, 버튼은 `TermButton` 또는 `SubmitButton`, 짧은 칸 이름은 `TermText` 가 거칩니다.

`custom_term_overrides` 로 공동체마다 메뉴 이름을 바꿀 수 있습니다.

1. 둘째 제주어를 고침: `{ "group": { "select": "alt" } }` → 모들 대신 구들
2. 첫째 제주어를 유지: `{ "select": "primary" }`
3. 문구를 직접 바꿈: `{ "website": { "text": "우리 마당" } }`
4. 모양이 깨지면 그 덮어쓰기를 모두 버리고 기본 사전을 씁니다.

표준어 이름에서는 `select` 가 문장을 바꾸지 않습니다. 직접 문구 `text` 만 그 이름을 바꿉니다.  
둘째 제주어가 없는 역할은 `alt` 를 골라도 첫째 제주어를 유지합니다.

사전은 `src/theme/dictionary.ts` 에 메뉴, 버튼, 역할이 들어 있습니다.  
`UNREGISTERED`(가입을 기다리는 사람)와 `GUEST`(로그인하지 않은 손님)는 화면 이름이며, 데이터베이스 역할 코드가 아닙니다.

키보드로는 `g` 를 누른 뒤 1.2초 안에 다음 글자를 누르면 메뉴로 이동합니다. 글을 쓰는 칸에서는 동작하지 않습니다. `g h` 는 첫 화면입니다.

## 7. 실행 순서와 주의

모들 폴더에서 실행합니다. 저장소 맨 위에서 `npm run dev` 를 하면 은혜로운 예배가 열리고, 모들이 아닙니다.

1. `cd modl`
2. `npm install`
3. 데이터베이스가 있을 때만 `.env.example` 을 `.env` 로 복사하고 `DATABASE_URL` 을 채웁니다.
4. `npm run typecheck` 로 타입 검사를 합니다. 데이터베이스가 없어도 됩니다.
5. `npm test` 로 단위 테스트를 합니다. 데이터베이스가 없어도 됩니다.
6. `npm run dev` 로 이 컴퓨터의 개발 서버를 켭니다. 주소는 `http://localhost:3210` 입니다. 이 주소는 공개 앱이 아닙니다.
7. 개발 서버가 처음 자료를 읽을 때 `src/server/db/migrations` 의 SQL 을 아직 적용하지 않은 것만 순서대로 실행합니다. 공개 앱도 같은 명령을 `modl-comm` Postgres에 아직 없는 것만 적용합니다. 손 작업이 필요하면 아래도 같습니다. 접속 문자열은 비밀 파일에만 둡니다.

```bash
psql "$DATABASE_URL" -f src/server/db/migrations/0001_init.sql
psql "$DATABASE_URL" -f src/server/db/migrations/0002_group_memberships.sql
psql "$DATABASE_URL" -f src/server/db/migrations/0003_qt_grace_reactions.sql
psql "$DATABASE_URL" -f src/server/db/migrations/0004_survey_responses.sql
```

주의할 점입니다.

1. `.env` 와 `secrets/` 는 깃에 올리지 않습니다.
2. 비밀번호를 코드 안에 적지 않습니다.
3. 공동체 운영 화면은 7단계까지 있고, 그 위에 질문과 답글이 있습니다.
4. 아직 열지 않은 메뉴는 "곧 열립니다" 자리만 있습니다. 새가족과 리더 자리 화면이 그렇습니다.
5. 폰, 패드, 맥 앱은 이미 만든 화면을 감싸기만 합니다.
6. 파이어베이스 자료 묶음과 엔에잇엔을 나중에 추가할 때는 이름 앞에 `[모들]_` 를 붙입니다.
7. 공개 화면 주소는 두 곳입니다. 파이어베이스는 `https://modl--modl-comm.asia-east1.hosted.app` 이고, 버셀 프로젝트 `modl-jeju` 는 `https://modl-jeju.vercel.app` 입니다. 서버를 이 컴퓨터에서 켜 두지 않아도 열립니다. 예전 임시 통로 주소는 더 이상 쓰지 않습니다. 프로젝트 이름이 `modl` 인 주소에는 올리지 않습니다.
8. 글꼴 파일은 제주특별자치도 공식 파일이고, 다른 명조나 고딕으로 바꾸지 않습니다. 메뉴 오른쪽 위 제목과 첫 화면의 "모들"만 제주명조이고, 사이드바, 본문, 버튼, 입력칸은 제주고딕입니다. 글꼴 파일을 유료로 팔거나 양도하지 않습니다.
9. 구글 시트 열쇠와 시트 번호 값은 비밀 이름 `GOOGLE_SHEETS_SERVICE_ACCOUNT`, `GOOGLE_SHEETS_SPREADSHEET_ID` 로만 둡니다. 문서와 깃에는 그 이름과 시트 제목만 적습니다.

## 8. 2단계 화면과 가입

화면 주소는 모들 개발 서버 `http://localhost:3210` 기준입니다.

1. `/` 첫 화면. 질문 창과 질문 목록입니다. 운영 메뉴는 분류 안에 있습니다.
2. `/account` 계정 만들기, 들어가기, 나가기. 이 화면에는 공동체 만들기와 사용 등급 고르기가 없습니다. 화면 아래의 계정을 눌러 이 화면을 엽니다. 사역자만 가입자 목록을 봅니다. 칸은 이름, 이메일, 성별, 전화번호, 다니는 교회입니다. 등급 칸은 없습니다. 임원과 일반 회원 화면에는 목록이 나오지 않고, 자료도 보내지 않습니다. 가입자가 없으면 표 머리만 있고 빈 목록입니다. 위쪽 분류 메뉴에는 가입자 항목을 넣지 않습니다.
3. `/signup/church` 가입이 끝난 뒤의 추가 입력. 교회 목록은 없고, 그 자리에서 교회를 등록합니다. 등록 칸은 교회이름, 담임목사, 주소, 전화번호, 주일 예배시간, 메모와 소속/예배/통역/시설 필터입니다. 지역 필터와 등급 고르기는 없습니다. 이미 다니는 교회가 있으면 첫 화면으로 돌아갑니다. 지도 열쇠가 없어도 교회는 계정에 저장되고, 핀만 없을 수 있습니다. `/community/new` 공동체 만들기는 로그인 화면에서 열리지 않습니다.
4. `/invite` 초대 코드 발급. 사역자와 임원만.
5. `/join` 가입 신청.
6. `/approvals` 승인 대기열. 승인하기와 거절하기.
7. `/roster` 교적부 목록. `/roster/new` 등록. `/roster/사람번호` 수정.
8. `/group` 모들 편성. 시즌 연도, 모들 추가, 테우리, 구성원 배정, 지난 편성.

가입은 아래 순서를 모두 지나야 정식 구성원이 됩니다.

1. 신청자는 계정이 있어야 합니다.
2. 초대 코드가 맞고, 기한이 남았고, 쓸 수 있는 횟수가 남아 있어야 합니다.
3. 신청한 교단과 공동체 교단이 같아야 합니다. 앞뒤 공백과 대소문자는 무시합니다.
4. 신청이 만들어지면 상태는 `PENDING` 입니다. 이 동안 정식 권한이 없습니다.
5. `PASTOR` 또는 `EXECUTIVE` 가 승인해야 명부에 정식으로 연결됩니다. 거절하면 `REJECTED` 이고 명부 줄은 생기지 않습니다.
6. 이 단계에서는 `require_approval` 값을 저장만 합니다. 그 값이 꺼져 있어도 관리자 승인을 기다립니다.
7. 승인할 때 같은 공동체에서 `user_id` 가 비어 있고 전화번호 숫자만 같은 명부 줄이 하나면 그 줄에 계정을 붙입니다. 이름과 역할은 그대로 둡니다.
8. 같은 전화번호의 미가입 줄이 없으면 새 구성원 줄을 만듭니다. 역할은 `MEMBER` 입니다.
9. 같은 전화번호의 미가입 줄이 둘 이상이면 추측하지 않고 승인을 멈춥니다. 교적에서 한 줄만 남긴 뒤 다시 승인합니다.

모들 편성은 이렇게 남깁니다.

1. 모들에는 해(`season_year`), 이름, 테우리가 있습니다.
2. 사람을 넣으면 `group_memberships` 에 연결 줄이 생기고, 명부의 `current_group_id` 가 그 모들을 가리킵니다.
3. 다른 모들로 옮기면 이전 연결의 `ended_at` 만 채우고 새 줄을 추가합니다.
4. 새 해로 편성하면 다른 해의 보관되지 않은 모들은 `is_archived=true` 가 됩니다. 줄과 연결 기록은 지우지 않습니다.
5. 보관된 모들에는 사람을 새로 넣지 않습니다.

## 9. 3단계 주일 기별

화면 주소는 `http://localhost:3210` 기준입니다.

1. `/bulletin` 지난 주보 목록. 예배 날짜가 늦은 것부터 보여 줍니다.
2. `/bulletin/new` 주보 만들기. 그 교회 담당자(사역자, `PASTOR`)만 보입니다. 위쪽 주보 입력에서 직접 적거나 붙여 넣고, 글 파일과 사진을 올립니다. 글 파일은 텍스트, 워드, 한글, PDF, RTF, ODT, HTML 입니다. 사진 글은 `QT_OCR_API_KEY` 가 있을 때만 읽습니다. 열쇠가 없거나 글을 읽지 못하면 파일을 저장하고 칸은 비워 둡니다. 없는 문장은 만들지 않습니다. 한 번 읽으면 그 주 예배를 함께 만들고, 부는 1부부터 3부까지이며 글에 있는 새벽·수요·금요·특별 예배도 같이 두고, 없는 순서는 넣지 않습니다. 십일조, 헌금, 봉헌은 순서와 광고에 넣지 않습니다.
3. `/bulletin/주보번호` 고치기 또는 보기. 담당자만 블록을 고칩니다. 임원은 아직 공개하지 않은 주보도 읽을 수 있고, 구성원은 발행된 주보만 읽습니다.
4. `/bulletin/share/공개표식` 로그인 없이 여는 공개 주소.

주보 표 `bulletins` 에 들어가는 칸은 이렇습니다.

1. `community_id` 어느 공동체인지.
2. `worship_date` 예배 날짜.
3. `service_label` 주보에서 읽은 예배 이름. 예전 주보와 글에 이름이 없으면 비워 둡니다.
4. `service_time` 주보에서 읽은 시각. 글에 시각이 없으면 그 예배 종류의 기본 시각만 둡니다.
5. `sermon_title` 설교 제목. 목록과 공유 카드에 나갑니다.
6. `scripture_text` 본문 말씀.
7. `preacher` 설교자.
8. `blocks_json` 블록 배열. 적은 순서가 화면에 보이는 순서입니다.
9. `is_public` 발행이면 참. 초안은 거짓입니다.
10. `share_token` 공개 표식. 발행할 때 한 번 만들고, 이미 있으면 다시 만들지 않습니다. 비공개로 돌려도 표식은 남겨 두고, 공개가 아니면 그 주소는 내용을 보여 주지 않습니다.

블록 종류는 다섯 종류입니다. 교회마다 순서가 달라도 됩니다.

1. 예배 순서. 순서 이름과 설명.
2. 설교. 제목, 본문 말씀, 설교자.
3. 임사자 명단. 맡은 일과 이름.
4. 찬양 목록. 곡명, 악보 그림 주소. 주소가 http 또는 https 일 때만 그림을 보여 줍니다.
5. 광고. 안내 글.

누가 무엇을 하는지입니다.

1. `PASTOR` : 만들기, 고치기, 순서 바꾸기, 발행, 비공개로 되돌리기.
2. `EXECUTIVE` : 발행된 주보와 아직 공개하지 않은 주보를 읽기. 만들지는 않습니다.
3. `MEMBER`, `NEWCOMER`, `CELL_LEADER` : 발행된 주보만 읽기.
4. 손님(GUEST) : 공개 표식 주소만. 목록과 초안은 보지 못합니다.
5. 다른 공동체 주보는 목록과 수정 화면에 나오지 않습니다.
6. 주보를 저장하면 그 교회 일정에 예배와 광고 일정이 들어갑니다. 예배는 주보에 적힌 날짜와 시각으로 한 줄이 생깁니다. 광고는 날짜, 시각, 예배 후처럼 일정이 보이는 줄만 넣습니다. 십일조, 헌금, 봉헌은 일정에 넣지 않습니다. 같은 주보를 다시 저장하면 그 주보로 만든 일정만 지우고 다시 넣습니다.

편지함으로 주보 파일을 받는 길은 아직 없습니다. `anyplan@me.com` 은 아이클라우드 편지함이고, 이 작업 환경의 편지 연결(지메일)에는 로그인되어 있지 않습니다. 그래서 그 주소로 보낸 파일을 읽지 못합니다. 담당자가 주보 만들기 화면에서 파일을 직접 올리면 그 주 예배를 만듭니다.

공유는 이렇게 동작합니다.

1. `KAKAO_JAVASCRIPT_KEY` 가 없으면 버튼은 제목, 날짜, 공개 주소를 복사합니다. 카카오톡 카드를 띄웠다고 말하지 않습니다.
2. 그 열쇠가 있으면 카카오톡 공유 카드를 띄웁니다.
3. `KAKAO_SHARE_TEMPLATE_ID` 가 숫자일 때만 그 꾸러미를 씁니다. 아니면 공개 페이지의 미리보기 제목과 설명을 씁니다.
4. 공개 페이지는 Open Graph(링크를 붙여 넣을 때 보이는 제목과 설명)로 설교 제목과 날짜, 설교자, 본문을 냅니다.
5. 표식이 틀리거나 비공개면 설교 내용과 그 미리보기를 내지 않습니다.

## 10. 4단계 출석과 일정

화면 주소는 `http://localhost:3210` 기준입니다.

1. `/attendance` 출석 첫 화면. 위쪽 버튼은 교회출석과 모들출석 두 개입니다. 교회출석을 누르면 내가 속한 교회가 나와 하나를 고릅니다. 모들출석을 누르면 내가 속한 모들이 나와 하나를 고릅니다. 화면 제목은 없습니다. 버튼 아래에 나의 출석현황이 있습니다. 그 아래 이번 달 출석률, 모들 만들기가 있습니다. 교회를 고르기 전에는 주보 자리에 “교회를 선택하라”가 나옵니다. 교회를 고르면 그 교회의 이번 주 주보와 예배 드리기 길이 나옵니다. 그 아래로 출석 모임 목록이 이어집니다. 사역자와 임원은 모임을 만듭니다.
2. `/attendance/session/모임번호` 식구 목록. 테우리는 자기 모들 식구가 위에 옵니다.
3. `/attendance/qr/표식` 본인 체크인. 버튼 문구는 말투 사전의 `check_in_btn` 입니다.
4. `/attendance/stats` 주간, 월간, 연간 출석률.
5. `/worship` 예배. 출석에서 고른 교회로 들어갑니다. 담당자는 쓸 언어마다 실시간 번역기 자막 링크를 저장합니다. 링크가 없는 언어는 고를 수 없습니다. 보는 사람이 언어를 고르면 서버가 그 링크를 읽어 자막을 화면 위 3분의 1에 보여 줍니다. 폰을 가로로 돌리면 그 자막만 전체 화면이 됩니다. 만든 예배는 위쪽 단추로 고르고, 그 예배의 순서, 내용, 광고를 보여 줍니다. 자막 주소는 보는 사람 화면에 적지 않습니다.
6. `/calendar` 월 달력. 로그인한 사람이 속한 교회의 일정과, 그 사람이 속한 모들의 일정만 보여 줍니다. 속하지 않은 교회나 모들 일정은 나오지 않습니다. 교회 일정은 모들 칸이 비어 있고, 모들 일정은 그 모들 번호가 있습니다. 그 날의 생일과 교회 절기, 읽어 온 구글 일정도 함께 칸에 놓습니다.
7. `/calendar/일정번호` 일정 수정과 삭제. 그 교회 담당자, 임원, 그 모들 테우리만 고칩니다. 다른 교회 일정은 열리지 않습니다.

출석 모임 `attendance_sessions` 에는 공동체, 부서, 제목, 날짜, QR 표식이 들어갑니다.

1. 부서는 `YOUTH`(청년부) 또는 `SCHOOL`(교육부)입니다.
2. 모임을 만드는 사람은 `PASTOR`, `EXECUTIVE` 입니다.
3. QR 표식은 모임마다 하나이고 서로 겹치지 않습니다.

출석을 남기는 방법은 세 종류입니다.

1. `SELF_QR` 본인 체크인. QR 경로에서 `check_in_btn` 을 누르면 상태는 `PRESENT` 입니다. 한 모임에 한 사람은 한 줄만 있고, 이미 있으면 다시 눌러도 덮지 않습니다. 토스트(짧은 안내)는 서버가 기록을 남긴 뒤에만 사전 문장을 보여 줍니다.
2. `GROUP_LEADER` 모들 테우리. 맡은 모들 식구만 한 번 터치로 `PRESENT`, `LATE`, `ABSENT`, `EXCUSED` 를 고릅니다. 다른 모들 식구는 고치지 못합니다.
3. `EXECUTIVE` 사역자와 임원. 모들이 없어도 공동체 전체 출석을 고칩니다. 테우리를 겸해도 이 방법으로 남깁니다.

보고픈 괸당 기준입니다.

1. 최근 출석 기록 가운데 사유 결석 `EXCUSED` 를 빼고, 남은 기록 세 개가 모두 `ABSENT` 이면 그 사람의 상태를 `LONG_ABSENT` 로 둡니다.
2. 기록이 없는 모임은 세지 않습니다. 사유 결석은 연속을 끊지 않고 횟수에서도 뺍니다.
3. 그 다음 기록이 `PRESENT` 또는 `LATE` 이면 `ACTIVE` 로 되돌립니다.
4. `GRADUATED`(졸업)는 이 규칙으로 바꾸지 않습니다.
5. 카드는 `PASTOR`, `EXECUTIVE`, 그리고 그 사람이 속한 모들의 테우리만 봅니다. 구성원과 새가족은 카드를 받지 않습니다.

출석률은 출석과 지각을 분자로, 출석·지각·결석을 분모로 합니다. 사유 결석은 분모에서 뺍니다.

1. 사역자와 임원은 공동체 전체를 봅니다.
2. 테우리는 자신이 맡은 모들 식구만 봅니다.
3. 그래프 옆에는 퍼센트 글자를 적어, 글자를 키워도 비율이 사라지지 않습니다.

일정 공개 범위입니다.

1. 종류는 `RETREAT`, `EVENT`, `BIRTHDAY`, `HOLIDAY`, `ETC` 입니다.
2. 등록, 수정, 삭제는 `PASTOR`, `EXECUTIVE`, `CELL_LEADER` 만 합니다.
3. `is_leader_only` 가 참이면 그 세 역할만 봅니다. 구성원과 새가족은 그 일정을 받지 않습니다.
4. 손님은 일정을 받지 않습니다.
5. 명부 `birth_date` 가 있으면 그 달 달력에 생일을 자동으로 보여 줍니다. 일정 줄을 따로 만들지 않습니다. 생일은 리더 전용이 아니고, 정식 구성원이면 봅니다.
6. 다른 공동체 일정은 목록에 나오지 않습니다.

월 달력은 이전 달, 다음 달, 날짜 칸으로 그 날의 일정을 보여 줍니다. 구글 달력 번호는 비밀 이름 `GOOGLE_CALENDAR_ID` 에만 있고 이 안내서에는 적지 않습니다. 이름이 modl 인 구글 달력의 실제 일정만 읽어 오며, 없는 일정은 만들지 않습니다.

교회 절기는 서력 교회력(해마다 날짜를 정하는 계산)으로만 칸에 적습니다. 모임 일정으로 저장하지 않습니다. 대림절은 시작 일요일부터 12월 24일까지, 사순절은 재의 수요일부터 부활절 전날까지 짧게 적습니다. 시작 날에는 대림절 시작, 재의 수요일, 사순절 시작이라고 적습니다. 성탄절, 주현절, 종려주일, 성금요일, 부활절, 승천일, 성령강림절은 그 날에만 적습니다.

구글 달력은 달력 번호와 열쇠가 있을 때만 보냅니다. 열쇠 값은 앱 호스팅 비밀 저장소 `GOOGLE_CALENDAR_API_KEY` 에만 있습니다.

1. `GOOGLE_CALENDAR_API_KEY` : 이름만 적습니다. 값은 이 안내서에 없습니다.
2. `GOOGLE_CALENDAR_ID` : 구글 달력 번호의 이름입니다. 값은 비밀 저장소에만 있습니다. 없으면 구글에 보내지 않고, 없는 일정은 만들지 않습니다.
3. `GOOGLE_CALENDAR_CLIENT_ID`
4. `GOOGLE_CALENDAR_CLIENT_SECRET`
5. `GOOGLE_CALENDAR_REFRESH_TOKEN`
6. 예전 로그인 열쇠 세 개와 달력 번호가 모두 있어도 보냅니다.
7. 보낼 수 없으면 동기화 버튼 자리에 안내만 보여 주고, 모들 달력은 그대로 씁니다. 보냈다고 말하지 않습니다.
8. 값이 있으면 저장할 때 구글에 보내고, 받은 번호를 `google_event_id` 에 남깁니다. 이미 번호가 있으면 그 일정을 고칩니다.
9. 구글에서 빼는 일이 실패하면 모들 일정은 지우지 않고 안내만 합니다.
10. 공개로 읽히면 열쇠 이름 `GOOGLE_CALENDAR_API_KEY` 로 읽고, 비공개면 시트 계정 비밀 이름 `GOOGLE_SHEETS_SERVICE_ACCOUNT` 로 읽습니다. 공유되지 않아 읽히지 않으면 구글 일정은 비워 둡니다. 값은 적지 않습니다.

## 11. 5단계 말씀, 기도, 행사 기록

화면 주소는 공개 주소 `https://modl--modl-comm.asia-east1.hosted.app` 기준입니다. 같은 화면이 이 컴퓨터의 개발 서버 `http://localhost:3210` 에도 있습니다.

1. `/qt` 말씀 목록과 등록. 사역자와 모들 테우리만 등록합니다.
2. `/qt/말씀번호` 본문, 질문, 묵상 답, 은혜, 내 답 이후의 다른 묵상.
3. `/prayer` 기도 글 작성과 목록. 함께 기도가 글마다 있습니다. 기도 편지 화면은 없습니다.
4. `/archive` 행사자료 목록. 제목, 행사 날짜, 있는 자료만 보여 줍니다.
5. `/quiz` 퀴즈 목록. 정한 시간에만 풀 수 있고, 푼 뒤에도 목록에 남습니다.
6. `/archive/행사번호` 사진과 유튜브 영상 칸.
7. `/quiz/퀴즈번호` 퀴즈 풀기. 시간이 아니면 풀 수 없습니다.

말씀 등록 칸은 날짜, 말씀 제목, 본문, 질문 목록, 사진이나 문서입니다.

1. 올린 파일 위치는 `source_file_url` 에 저장합니다. 파일 자체는 `public/uploads` 에 있고 깃에 올리지 않습니다.
2. `QT_OCR_API_KEY` 가 있을 때만 사진에서 비어 있는 본문과 질문을 채웁니다. 이 열쇠는 사진만 읽습니다.
3. 열쇠가 없으면 사람이 직접 적습니다. 버튼은 열쇠가 필요하다는 안내만 하고, 읽은 글을 만들지 않습니다.
4. 구성원은 `submit_qt_btn`(말씀 담았수다, 표준어 공동체에서는 묵상 작성 완료)으로 답을 저장합니다. 다시 저장해도 처음 시각은 바꾸지 않습니다.
5. 알림 목록은 그 시각 이후, 같은 말씀에 올라온 다른 사람 묵상만 보여 줍니다. 내 답이 없으면 알림은 비어 있습니다.
6. 각 묵상의 `grace_reaction_btn`(은혜 쏨빡)은 한 사람당 한 번만 `grace_count` 를 올립니다. 기록은 `qt_grace_reactions` 표입니다.

기도 공개 범위는 네 종류입니다. 목록은 서버에서 역할과 소속 모들로 거릅니다. 다른 공동체 글은 나오지 않습니다.

1. `PUBLIC` 모두 공개. 정식 구성원이 보고 쓸 수 있습니다.
2. `GROUP_ONLY` 모들만. 그 모들 식구, 그 모들 테우리, 사역자만 봅니다.
3. `LEADER_ONLY` 테우리만. 그 모들 테우리와 사역자만 봅니다.
4. `PASTOR_ONLY` 사역자만. 작성자 본인도 자기 글을 봅니다.
5. 익명이면 작성자가 아닌 사람에게는 작성자 번호와 이름을 빼서 보냅니다. 작성자 본인은 자기 글을 봅니다.
6. `pray_together_btn`(혼디 기도햄수다)은 한 사람 한 번이고 `pray_together_count` 가 오릅니다.
7. 다정한 기별의 수신자는 기도 작성자입니다. 익명 글이어도 수신자 번호는 작성자 본인으로 저장합니다. 보낸 기별 목록에는 그 작성자 이름을 적지 않고 익명으로만 보여 줍니다.
8. 받은 기별은 수신자만 읽음으로 둘 수 있습니다.

행사 기록은 제목, 사진 주소 목록, 유튜브 주소 목록입니다. 유튜브 주소만 영상 칸으로 재생하고 다른 사이트 주소는 받지 않습니다.

퀴즈는 질문 JSON(질문을 담은 자료 모양)과 제출 점수 JSON을 저장합니다. 푸는 화면에는 정답 번호를 넣지 않습니다. 구성원이 고른 답을 서버가 세어 그 사람 점수를 저장합니다. 같은 사람이 다시 풀면 이전 점수를 새 점수로 바꿉니다. 사람 구역과 기도 편지, 설문, 승인 메뉴는 없고 그 일은 사용자 이름을 눌러 연 계정에서 권한 있는 사람만 열며, 열린 설문은 구성원 알림을 누르면 열리고, 재정 화면은 시트1에 있는 금액만 보여 주며, 행사자료는 제목과 행사 날짜와 있는 자료만 목록으로 보고, 퀴즈 메뉴는 남아 정한 시간에만 풀 수 있고 그달 맞힌 수가 가장 많으며 동점이면 먼저 낸 사람이 퀴즈왕입니다. 폰 메뉴는 위쪽 두 줄이고, 각 줄이 화면 너비를 그 줄의 메뉴 개수대로 같은 칸으로 나눕니다. 글자가 칸 안에 들어가게 두고, 한 줄에 다 안 들어가면 같은 너비로 다음 줄에 이어 채웁니다. 패드와 넓은 화면은 세로 목록이며 퀴즈는 예배, 행사자료는 운영에 두며, 본문은 폰에서 좁은 폭을 채우고 패드 오른쪽 여백은 넓은 화면보다 조금 좁되 답답하지 않게 두며, 계정에 들어오면 교인·모임·초대·새가족·승인·설문·교회·금지어가 바로 탭으로 열리고 그 안에서 다시 눌러 들어가지 않으며, 교회 탭에는 등록된 교회 목록이 바로 나오고, 나가기는 그 화면 맨 아래에 두고, 금지어는 한 칸에 쉼표로 적어 저장하며, 교회 지역은 주소의 한글과 영문 지명으로 제주시와 서귀포시를 가리고, 서귀포가 아닌 제주와 조천·애월·한림 같은 곳은 제주시로 두며, 지명을 못 읽으면 비웁니다. 교회 목록과 지도의 지역 필터는 없고, 소속·예배·통역·시설 태그를 켜고 끄며, 태그는 주소로 만들지 않습니다.

## 12. 6단계 살림, 내보내기, 설문, 회의록

화면 주소는 공개 주소 `https://modl--modl-comm.asia-east1.hosted.app` 기준입니다. 같은 화면이 이 컴퓨터의 개발 서버 `http://localhost:3210` 에도 있습니다.

1. `/finance` 살림. 분류, 거래, 예산 대비 막대, 기간 영수증, 엑셀 받기.
2. `/export/roster` 교적 엑셀. 누르면 바로 `modl-roster.xlsx` 가 내려옵니다.
3. `/export/attendance` 출석 엑셀. 누르면 바로 `modl-attendance.xlsx` 가 내려옵니다.
4. `/export/finance` 살림 엑셀. 누르면 바로 `modl-finance.xlsx` 가 내려옵니다.
5. `/finance/receipts?start=시작일&end=종료일` 그 기간 영수증 사진 압축 `modl-receipts.zip`.
6. `/survey` 설문 목록과 만들기.
7. `/survey/설문번호` 답 보내기. 로그인 없이 열리는 설문도 이 주소입니다.
8. `/survey/설문번호/results` 설문 결과.
9. `/minutes` 회의록.

살림은 사역자와 임원만 보고 적습니다. 교적 엑셀, 출석 엑셀, 회의록도 사역자와 임원만 받습니다. 다른 공동체 줄은 넣지 않습니다.

1. 분류는 부서나 행사, 수입 또는 지출, 이름, 배정 예산입니다.
2. 거래는 날짜, 금액, 설명, 영수증 사진 주소 여러 개입니다. 종류는 고른 분류를 따라갑니다.
3. 분류마다 같은 종류의 거래를 예산으로 나눈 비율을 막대로 보여 줍니다. 비율 글자도 함께 보여 글자가 커져도 막대만으로 숨지 않습니다. 예산이 0이면 100퍼센트로 꾸미지 않습니다.
4. 시작일과 종료일을 고르면 그 사이 영수증만 압축에 넣습니다. 시작일과 종료일도 포함합니다.
5. 그 기간에 사진이 없거나 사진을 읽지 못하면 빈 압축을 주지 않고, 화면에 그 사실을 알려 줍니다.

구글 시트 연결은 파이어베이스 프로젝트 `modl-comm` 에 있습니다. 전용 계정 메일은 `modl-sheets@modl-comm.iam.gserviceaccount.com` 입니다. 시트 제목은 `modl_sheet` 이고, 탭 이름은 `시트1` 입니다. 비밀 저장소에 둔 이름은 아래 둘뿐이고, 값은 적지 않습니다.

1. `GOOGLE_SHEETS_SERVICE_ACCOUNT`
2. `GOOGLE_SHEETS_SPREADSHEET_ID`
3. 열쇠 파일 내용, 개인 열쇠 글, 시트 번호 값, 칸 안의 글은 안내서와 깃에 올리지 않습니다.

설문은 제목, 질문(한 줄에 하나), 로그인 없이 답 받기, 마감입니다.

1. 마감 시각이 지나면 답을 거절합니다. 마감이 없으면 열려 있습니다.
2. `allow_anonymous` 가 켜진 설문만 로그인 없이 답을 보냅니다. 그때는 구성원 번호를 저장하지 않습니다.
3. 결과는 설문을 만든 사람과 사역자, 임원만 봅니다. 다른 공동체 결과는 열지 않습니다.
4. 설문 만들기는 사역자와 임원만 합니다.

회의록은 날짜, 참석자, 본문, 첨부 주소입니다. 사역자와 임원만 보고 저장합니다.

## 13. 7단계 열린 안뜨레

화면 주소는 공개 주소 `https://modl--modl-comm.asia-east1.hosted.app` 기준입니다.

1. `/website` 편집 화면. 사역자와 임원만 블록을 놓고, 디자인을 고치고, 저장합니다.
2. `/site/주소이름` 로그인 없이 여는 공개 페이지. 주소 이름은 공동체 `slug` 입니다. 한빛공동체는 `/site/hanbit-phase2` 입니다.
3. `/@주소이름` 도 같은 공개 페이지로 열립니다. 예: `/@hanbit-phase2`. 실제 저장 경로는 `/site/주소이름` 입니다.

블록은 순서를 바꾸고 뺄 수 있습니다.

1. 소개: 대표 소개, 본문, 사진첩, 영상, 배너.
2. 예배와 방문: 예배 시간, 오시는 길 지도, 자주 묻는 질문, 방문자 문의 양식.
3. 소식과 연결: 공지, 행사 디데이, 팝업 알림, 자료실, 소셜 링크.
4. 앱 연동 세 종류: 최신 공개 주일 기별, 생일과 공휴일을 뺀 다가오는 일정, 로그인 없이 제출되는 설문.

연동 블록은 `plan_tier` 가 `PRO` 일 때만 공개 페이지에 그립니다. `FREE` 는 편집 화면에 유료 등급이 필요하다는 안내만 보여 주고, 공개 페이지에는 그 블록을 그리지 않습니다.

디자인은 `theme_json` 에 글꼴, 배경색, 버튼 모양을 저장합니다. 편집 화면 미리보기에 바로 반영됩니다.

검색 정보는 `seo_json` 입니다.

1. 검색 제목, 검색 설명, 대표 이미지 주소를 메타 태그로 냅니다.
2. 검색 노출이 꺼지면 `noindex` 를 냅니다.
3. 편집 화면은 공개 주소의 QR 이미지를 보여 줍니다.
4. 공개 페이지를 열 때마다 `visit_count` 가 1 오릅니다.

방문 문의는 이름, 연락처, 메시지를 `website_inquiries` 에 저장합니다.

1. 편집 화면에서 목록을 보고 처리 완료로 표시합니다.
2. 문의가 저장되면 사역자와 임원 알림 목록에 바로 나타납니다.
3. `INQUIRY_PUSH_KEY` 가 없으면 앱 안 알림만 하고, 푸시를 보냈다고 말하지 않습니다.
4. 다른 공동체 문의는 목록에 나오지 않습니다.

요청된 7단계 웹 범위는 여기서 끝입니다. 그 다음 공동체 기능은 만들지 않습니다.

## 14. 폰, 패드, 맥 앱

이 앱은 7단계까지 만든 웹을 네이티브 껍데기(웹을 기기 창 안에 띄우는 틀)로 감쌉니다. 화면, 권한, 제주어 말투 사전을 다시 짜지 않습니다. 웹은 `modl-comm` 앱 호스팅에 올라가 있습니다.

1. 대상은 아이폰, 아이패드, 맥입니다. 프로젝트는 하나이고, 맥은 Mac Catalyst(맥 카탈리스트, 아이폰 앱을 맥 창으로 돌리는 방식)입니다. 세 기기 모두 같은 묶음 이름을 씁니다. 맥이라고 이름 앞에 다른 말을 붙이지 않습니다. 맥 앱은 스토어 규칙 때문에 샌드박스(앱이 컴퓨터의 다른 파일을 마음대로 열지 못하게 가두는 울타리) 안에서 돌고, 인터넷에는 접속할 수 있습니다.
2. 프로젝트 경로는 `apple/Modl.xcodeproj` 입니다.
3. 폰에서는 위쪽 두 줄 탭으로 분류와 메뉴가 열립니다. 그 위에 제목 줄은 두지 않습니다. 아이패드와 넓은 창에서는 왼쪽 분류 메뉴와 넓은 칸이 열립니다. 맥에서는 창이 열리고, 키보드로 `command` 와 쉼표를 누르면 서버 주소 칸으로 돌아갑니다. 이 단축키는 맥의 설정 메뉴가 원래 쓰던 자리이므로, 설정 메뉴를 서버 주소로 바꿉니다. 같은 단축키를 하나 더 넣으면 앱이 켜지자마자 멈춥니다.
4. 글자가 커져도 안내 문구는 줄바꿈되고, 스크롤로 이어서 읽습니다. 한 줄로 잘라 숨기지 않습니다.
5. 서버 주소는 빌드에 넣지 않습니다. 앱을 연 사람이 설정으로 적습니다. 주소가 없으면 "서버 주소는 나중에 연결됩니다" 안내가 보이고, 빈 오류 화면은 나오지 않습니다. 공개 웹 주소는 `https://modl--modl-comm.asia-east1.hosted.app` 입니다. 그 주소를 앱 설정에 적으면 같은 화면이 열립니다.
6. 앱 아이콘은 1024×1024 그림 한 장입니다. 파일은 `apple/Modl/Assets.xcassets/AppIcon.appiconset/AppIcon.png` 입니다. 아이폰, 아이패드, 맥이 이 파일 하나를 같이 씁니다. 맥 칸은 512 포인트에 2배(픽셀로 세면 1024)로 적혀 있습니다. 영어 modl. 는 원래 갈색이고 위치도 그대로입니다. 한글 모들만 검은색입니다. 글자를 다시 그리거나 자르지 않습니다. 비어 있던 칸은 선명한 민트 한 색(`#00C4A7`)입니다. 프로젝트 화면에 이미 쓰던 민트 색은 없어서 이 색을 골랐습니다. 투명한 칸은 남기지 않습니다. 웹의 파비콘과 애플 터치 아이콘은 아직 `public/modl-icon.png` 원본입니다. 화면 왼쪽 위 로고는 `public/modl-logo.png` 입니다.
7. 스토어에 보이는 판 번호는 1.0 이고, 테스트플라이트 빌드 번호(같은 판을 다시 올릴 때마다 하나씩 오르는 번호)는 8 입니다.
8. 앱은 보통의 보안 주소(HTTPS)만 씁니다. 수출 규정은 암호화 예외로 답합니다. 그래서 정보 목록의 암호화 예외 항목은 꺼져 있습니다. 이 답이 비면 테스트플라이트에 빌드가 보이지 않습니다.

실행 순서입니다. 맥과 Xcode 가 있을 때 합니다.

1. `apple/Config/Signing.local.xcconfig.example` 을 `Signing.local.xcconfig` 로 복사합니다. 그 파일은 깃에 올리지 않습니다.
2. `APPLE_TEAM_ID` 와 `MODL_BUNDLE_ID` 가 있을 때만 그 복사본에 값을 채웁니다.
3. Xcode 로 `apple/Modl.xcodeproj` 를 엽니다.
4. 실행 대상을 아이폰 시뮬레이터, 아이패드 시뮬레이터, 또는 My Mac (Mac Catalyst) 중에서 고릅니다.
5. 앱이 열리면 서버 주소를 적기 전에는 안내만 보입니다.

테스트플라이트에 올리려면 아래 이름이 모두 있어야 합니다. 값은 코드에 적지 않습니다.

1. `APPLE_ID` : 애플 개발자 계정.
2. `APPLE_TEAM_ID` : 팀 번호.
3. `MODL_BUNDLE_ID` : 묶음 식별자.
4. `APP_STORE_CONNECT_API_KEY_ID` : 앱스토어 커넥트 API 열쇠 번호.
5. `APP_STORE_CONNECT_API_ISSUER_ID` : 열쇠 발행 번호.
6. `APP_STORE_CONNECT_API_KEY_PATH` : `.p8` 열쇠 파일 경로.

이름이 갖춰진 맥에서 `sh apple/upload-testflight.sh` 를 실행합니다. 이 리눅스 환경에는 Xcode 와 위 비밀이 없어서 아카이브, 시뮬레이터, 테스트플라이트 업로드를 하지 않습니다.

## 15. 질문과 답글

첫 화면은 가운데 입력창과, 그 아래 질문 카드입니다. 목사 지정과 보이는 곳은 입력창 아래의 작은 선택입니다. 인공지능이 답하지 않습니다. 로그인하지 않았을 때만 제목 아래에 "로그인하면 모바일주보와 일정관리, 재정관리 등 여러가지 기능을 사용할 수 있습니다." 가 보입니다. 같은 자리에 로그인 안내와 카카오 로그인, 네이버 로그인 버튼이 있습니다. 로그인한 뒤에는 그 안내와 로그인 버튼을 치우고, 질문을 적는 칸이 나옵니다. 이메일 로그인은 그대로 계정 화면에 있습니다. 첫 화면의 "모들"과 화면 위 제목은 제주명조이고, 첫 화면 모들보다 다른 명조 제목은 더 작습니다. 나머지 글자는 제주고딕입니다.

1. 질문하는 사람은 목사 한 명을 지정할 수 있습니다. 지정하지 않으면, 그 질문을 볼 수 있는 목사가 답합니다.
2. 보이는 곳은 하나만 고릅니다. 목사에게만, 또래에게만, 선배에게만.
3. 또래와 선배는 교인 카드의 구분입니다. 없음, 또래, 선배 중 하나입니다.
4. 목사 등록은 교인 카드에서 역할을 목사로 두는 일입니다. 임원과 사역자가 할 수 있습니다.
5. 답글은 승인 전에 질문한 사람에게 보이지 않습니다. 승인 후에 그 사람에게만 본문이 보입니다.
6. 답글 승인은 승인 화면에서 합니다. 임원이 할 수 있습니다. 답글을 쓴 목사는 자기 글을 승인하지 못합니다.
7. 질문 한 건의 주소는 `/question/질문번호` 입니다.

## 16. 지도

분류 메뉴의 연결 안에 지도가 있습니다. 주소는 `/map` 입니다. 로그인하지 않아도 열립니다. 지도가 화면의 중심입니다. 넓은 화면은 장소 검색과 교회 필터가 지도 아래 가로로 넓은 창에 있습니다. 소속, 예배, 통역, 시설 네 묶음은 접히거나 잘리지 않고 한 번에 보이며, 그 창에 교회정보수정요청과 메일 주소가 있고 메일 주소는 누르면 메일이 열립니다. 폰은 평소에 분류가 화면 아래에 내려가 있고 지도가 보입니다. 분류를 누르면 그 창이 위로 올라와 소속, 예배, 통역, 시설을 고릅니다. 교회를 고르면 그 자리에 교회 소개가 나옵니다. 닫기를 누르면 분류와 소개가 다시 아래로 내려가고 지도가 보입니다. 아래쪽에 가려진 태그는 그 목록을 손가락으로 밀어 올려 누를 수 있고, 완료 버튼은 밀어 올리는 동안에도 그대로 보입니다. 완료를 누르면 닫히며 그때 켠 태그만 지도 핀에 남습니다. 교회 핀을 누르면 검색 대신 그 교회 정보가 나옵니다. 계정에서 교회 목록을 고칠 수 있는 사역자에게만 그 정보 창에 수정 버튼이 보입니다. 수정 버튼을 누르면 창이 뜨고, 교회이름, 담임목사, 주소, 전화번호, 주일 예배시간, 메모, 소속·예배·통역·시설 태그를 고칠 수 있습니다. 저장에 성공하면 그 창이 닫히고, 지도와 계정 교회 목록에 같이 반영됩니다. 닫기 버튼은 그대로 있습니다. 저장에 실패하면 창을 닫지 않고 이유를 보여 줍니다. 교회가 아닌 곳을 누르면 정보 대신 검색과 필터가 다시 나옵니다. 장소를 고르면 그 정보도 같은 아래 창에 있고, 지도 전체를 덮지 않습니다. 지도 판은 브라우저에서 불러 서버가 그 묶음을 찾지 못해 화면이 멈추지 않게 합니다. 지도 그림만 맵박스를 씁니다. 화면이 `/map` 이어도 맵박스에 붙이는 주소는 공개 주소 한 줄입니다. 지도 조각은 서버가 그 주소로 받아 오고, 그림을 그리는 열쇠는 실행 중에 비밀 저장소에서 읽어 이 화면에만 넘깁니다.

1. 장소 검색은 식당과 숙소만 보여 줍니다. 학교처럼 다른 장소는 목록에 넣지 않습니다.
2. 교회 핀이나 검색한 장소를 누르면 오른쪽 정보 칸이 열립니다. 교회는 교회이름, 담임목사, 주소, 전화번호, 주일 예배시간, 메모를 보여 줍니다. 검색 장소는 이름과 주소를 보여 줍니다. 이름, 주소, 길안내, 버스 목록은 구분선으로 나뉩니다.
3. 길안내는 자동차, 도보, 버스 세 가지입니다. 시작은 내 위치입니다. 자동차와 도보는 맵박스 길찾기 응답에 선이 있을 때만 그립니다. 없는 길은 만들지 않습니다. 지도에 들어오면 기본 화면은 제주도 전체입니다. 내 위치가 찾아지면 그 점을 가운데 두고 반경 10km가 보이게 확대합니다. 위치를 못 찾으면 제주도 화면을 유지하고, 이때는 오류 문구를 띄우지 않습니다. 따라가기는 지금 고른 실제 길이 있을 때만 켜집니다. 누르면 실제 위치로 안내하고, 선을 따라 카메라가 날아가지 않습니다. 길에서 약 100m 벗어나면 "재탐색"을 짧게 보여주고, 같은 수단으로 다시 길을 찾습니다. 자동차와 도보는 맵박스만, 버스는 제주 버스 응답만 다시 부릅니다. 새 응답에 선이 없으면 그리지 않습니다. 빨리 움직이면 넓게 보고, 천천히 움직이면 지금 있는 곳이 크게 보입니다. 위치를 못 찾아 안내를 시작하지 못하면 그 이유를 짧게 알려 줍니다.
4. 버스는 제주 버스 정보만 씁니다. 부르는 주소는 정의서에 있는 `http://busopen.jeju.go.kr/OpenAPI/service/bis/Station2`, `Bus`, `BusArrives`, `StationRoutePs`, `StationRoutePr` 입니다. 정류장 좌표와 노선은 그 응답에 있을 때만 보여 줍니다. 버스 번호는 버튼이고, 색은 응답의 노선 색을 따릅니다. 색이 없으면 지선은 초록, 간선은 파랑, 급행은 빨강만 씁니다. 번호를 누르면 그 노선의 정류장 좌표만 잇습니다. 도착은 응답의 산출 시각이 최근 30분 안일 때만 보여 줍니다. 제주가 아닌 장소에는 길을 만들지 않고 "제주 버스 정보입니다." 라고만 알려 줍니다. 정의서의 보안 항목이 열쇠 없음이라 버스 열쇠는 두지 않습니다.
5. 검색이나 길이 실패하면 그 문장만 보여주고, 가짜 좌표를 그리지 않습니다.
6. 교회 목록은 이름을 눌러 연 계정 화면의 교회 탭에 바로 나옵니다. 전체·제주시·서귀포시 필터는 없고, 소속·예배·통역·시설 태그를 켜고 끕니다. 같은 묶음은 하나라도 맞으면 되고, 다른 묶음은 모두 맞아야 하며, 아무것도 안 켜면 등록된 교회가 다 보입니다. 태그는 수정에서만 켜고, 주소로 짐작해 넣지 않습니다. 사역자가 교회를 직접 넣거나, 같은 칸 이름의 엑셀로 넣습니다. 지도 검색으로 넣은 교회는 검색 결과에 있던 이름, 주소, 전화번호만 적습니다. 담임목사와 주일 예배시간은 결과에 없으면 빈칸입니다. 메모는 지도 검색으로 등록했다고만 적습니다.
7. 지도 핀은 그 목록에서 주소가 있고 좌표를 찾은 교회만입니다. 로그인하지 않아도 운영 공동체(주소 이름 modl)의 교회 핀이 보입니다. 등록된 교회가 없으면 빈 상태입니다.
8. 교인 주소 핀은 지도 화면에서 본인이 동의한 뒤에만 나옵니다. 동의 문구는 "이 주소를 데리러 가는 사역자에게 지도로 보여 줍니다." 입니다. 동의한 시각을 저장하고, 동의를 거두면 핀을 지웁니다. 핀은 본인, 사역자, 임원만 봅니다.

## 17. 앱 호스팅

공개 화면은 Firebase App Hosting 에 있습니다. 프로젝트 아이디는 `modl-comm` 이고, 백엔드(올리는 단위) 이름은 `modl` 이며, 지역은 `asia-east1` 입니다. 설정 파일은 `modl/` 안에만 있습니다. 저장소 맨 위의 `firebase.json` 은 예배 앱용이라 바꾸지 않습니다.

1. 공개 주소: `https://modl--modl-comm.asia-east1.hosted.app`
2. 자료는 `modl-comm` 의 Postgres입니다. 공개 앱은 `127.0.0.1` 에 접속하지 않습니다.
3. 비밀번호는 비밀 저장소 `modl-db-password` 에만 있습니다. 접속 문자열은 코드, 이 안내서, 커밋, 풀 리퀘스트에 적지 않습니다.
4. 인스턴스 이름, 사용자 이름, 데이터베이스 이름은 `apphosting.yaml` 의 환경 변수로만 적습니다.
5. 표가 없으면 공개 앱이 처음 자료를 읽을 때 `src/server/db/migrations` 의 명령을 없는 것만 순서대로 실행합니다.
6. 같은 앱을 버셀 프로젝트 `modl-jeju` 에도 올려 두었습니다. 주소는 `https://modl-jeju.vercel.app` 입니다. 화면을 만드는 함수는 데이터베이스가 있는 대만 옆, 홍콩(`hkg1`)에서 돕니다. 버셀에는 대만 지역이 없어서 가장 가까운 홍콩을 씁니다. 파이어베이스 배포는 지우지 않습니다. 프로젝트 이름이 `modl` 인 곳에는 올리지 않습니다.
7. 버셀에는 시트, 달력, 맵박스 열쇠, 데이터베이스 이름을 같은 비밀 이름으로 넣었습니다. 값은 이 안내서에 적지 않습니다. 버셀에서 데이터베이스 인증서를 받으려면 비밀 이름 `GOOGLE_SQL_ADMIN_CREDENTIALS` 가 필요합니다. 맵박스 허용 주소 설정은 바꾸지 않았고, 지도 조각은 여전히 파이어베이스 공개 주소만 붙여 받아 옵니다.

다시 올릴 때는 모들 폴더에서 아래를 실행합니다. 비밀번호를 명령에 붙이지 않습니다.

```bash
cd modl
npx -y firebase-tools@latest deploy --only apphosting --project modl-comm
```
