# 은혜로운 예배

한 주의 예배를 준비하고, 예배 전에 빠진 항목을 점검한 뒤, 그 순서대로 화면에 송출하는 앱입니다. 화면 제목은 **은혜로운 예배**입니다.

필수 점검이 끝나기 전에는 예배를 시작할 수 없습니다. 순서 편집이나 진행 화면에서 **예배 시작**을 누르면, 빠진 항목이 `점검을 마쳐 주세요: …`로 나옵니다.

송출은 **데스크톱 앱 직접 연결**이 본선입니다. 조작 컴퓨터와 송출 컴퓨터에 각각 앱을 설치하고, 같은 로컬 네트워크에서 지금 두 줄 자막만 보냅니다. 송출 앱이 아직 없을 때만 설정의 **크롬용 메인** / **크롬용 오버레이** 링크를 폴백으로 씁니다. 송출 화면에 IP를 적지 않습니다.

전체 구조는 루트 [`전체구조안내서.md`](./전체구조안내서.md)를 보세요.

## iPhone·iPad 슬라이드 리모컨

모바일 앱 표시 이름은 **은혜로운 예배 Remote**입니다. **현재 예배 슬라이드를 넘기는 일만** 합니다. 주보·사람·라이브러리·전체 설정은 데스크톱 조작 앱에서 합니다. 송출은 Mac/Windows 데스크톱 앱을 그대로 씁니다. 설치·시뮬레이터·실기기 단계는 [`docs/mobile-operator-install.md`](./docs/mobile-operator-install.md)에 있습니다.

```bash
npm run mobile:sync
npx cap open ios
```

## 성도(교인) 앱 — 제거됨

성도용 `/member`·커뮤니티·기도함·`ios-member` Capacitor 셸은 **사용하지 않아 완전 삭제**했습니다.  
제품은 **Operator(조작 Remote)·데스크톱·모들(교회 연결)** 만 유지합니다.

## 데스크톱 앱 설치

송출은 Windows·Mac 모두 같은 로컬 직접연결(포트 `18765`)입니다. 조작 / 송출(메인) / 오버레이 세 가지로 실행합니다. 자세한 단계는 [`docs/desktop-install.md`](./docs/desktop-install.md)에 있습니다.

### Windows

1. `npm run desktop:pack:win` → 결과물 `desktop-dist/`
2. `EunhyeWorship-*-portable.exe` 또는 `win-unpacked/은혜로운 예배.exe`
3. `desktop/portable-shortcuts.ps1`로 조작·송출·오버레이 바로가기
4. 설치형 Setup: `npm run desktop:pack:win:setup`

### macOS

1. Mac에서 `npm run desktop:pack:mac` → 결과물 `desktop-dist/`
2. `EunhyeWorship-*-mac-*.dmg`를 열어 **은혜로운 예배.app**을 Applications로 드래그
3. 같은 폴더의 `.command` 바로가기를 더블클릭합니다.
   - **은혜로운 예배 조작**
   - **은혜로운 예배 송출**
   - **은혜로운 예배 오버레이**
4. 처음 열 때 Gatekeeper 안내가 나오면 **시스템 설정 → 개인 정보 보호 및 보안**에서 허용합니다.
5. 로컬 네트워크 권한을 물으면 허용합니다. (송출 포트 `18765`)

Intel/Apple Silicon용 dmg·zip이 함께 만들어집니다. 지금 Mac 한 대용만 필요하면 `npm run desktop:pack:mac:current`를 씁니다.

### 조작 컴퓨터

1. **은혜로운 예배 조작**을 엽니다.
2. 로그인 뒤 **설정**으로 갑니다.
3. **송출 컴퓨터 찾기**를 누르거나 IP를 넣습니다.
4. **기본값 저장**을 누릅니다. 껐다 켜도 다시 붙습니다.
5. 예배 **진행**에서 슬라이드를 넘기면 송출에 지금 두 줄만 갑니다. 본문 파일 전체는 올리지 않습니다.

### 송출 컴퓨터

1. **은혜로운 예배 송출**(또는 오버레이)을 엽니다.
2. 메뉴 없이 받을 준비만 합니다.
3. 방화벽·로컬 네트워크 권한을 허용합니다. (포트 `18765`)

### 개발 중 확인

```bash
npm run desktop:build-web
npm run desktop:dev
npx electron . --mode=output --display=main
```

## 웹 실행 (참고)

웹도 유지되지만, 송출 본선은 데스크톱 직접 연결입니다. Node.js 20 이상이 필요합니다. `.env.example`을 복사해 `.env.local`을 만들고 Firebase 값을 채운 뒤 실행합니다.

```bash
npm install
npm run dev
```

브라우저에서 [http://localhost:3000](http://localhost:3000)을 엽니다.

```bash
npm test
npm run build
npm start
```

`npm test`는 `lib`의 테스트를 돌립니다. `npm start`는 빌드된 웹 앱을 띄웁니다.

## 데이터

교회 목록과 예배 데이터는 브라우저마다 따로 두지 않습니다. Firebase 프로젝트 `live-interpret-db65e`의 최상위 `church` 경로만 사용합니다. `live-interpret`, `cheil`, `jifc` 경로는 읽지도 쓰지도 않습니다. 경로 맵은 [`docs/firebase-data-map.md`](./docs/firebase-data-map.md), 콘솔에 붙일 규칙은 [`docs/firebase-rules-paste.json`](./docs/firebase-rules-paste.json)입니다.

전체 운영자 한 명이 로그인하면 교회를 추가하고, 각 교회 운영자의 이메일·비밀번호·권한을 만듭니다. 비밀번호는 Firebase 인증에만 있고 저장소나 화면에 적지 않습니다. 교회 운영자는 전체 운영자가 만들어 주며, 자기 교회만 보고 다른 교회를 추가하거나 다른 교회 데이터를 보지 못합니다. 전체 운영자가 어느 브라우저에서 교회를 추가해도 교회 목록은 같습니다.

교회 안의 역할은 보기, 준비, 진행, 송출, 사람·찬양, 설정·계정입니다. 한 이메일에 역할을 여러 개 둘 수 있고, 그 권한은 그 교회 안에서만 동작합니다. 설정·계정 역할만 그 교회의 다른 이메일을 바꿉니다.

`firebase/church.rules.json`은 `church` 규칙만 담습니다. 기존 데이터베이스 규칙에 이 키만 합치고, 다른 최상위 경로는 그대로 둡니다.

## 화면

| 경로 | 하는 일 |
| --- | --- |
| `/` | 오늘 기준 일주일 일정, 다음 예배 또는 진행 중인 예배 |
| `/prepare` | 점검 목록, 주보 가져오기, 이번 주 예배, 알림 |
| `/services` | 예정과 지난 예배 |
| `/services/new` | 예배 만들기. 기본 순서, 빈 순서, 기존 예배 복사 |
| `/services/[id]` | 날짜·시간·장소, 순서, 담당, 광고, 점검 |
| `/services/[id]/live` | 순서 넘기기, 시작, 마치기. 진행 중에는 왼쪽·오른쪽 방향키로도 넘김 |
| `/services/[id]/output` | 송출 컴퓨터에 조작 화면이 보낸 두 줄만 표시 |
| `/services/[id]/slides` | 순서별 화면과 문구 수정 |
| `/services/[id]/bulletin` | 주보 보기와 인쇄 |
| `/people` | 이름, 역할, 전화, 활동 여부 |
| `/songs` | 번호, 곡명, 조, 화면 표시 |
| `/settings` | 교회 이름, 배경, 자막 위치, 송출 컴퓨터(찾기/IP), 크롬용 송출 링크 |
| `/receive` | 송출 앱 전용. 받을 준비와 지금 두 줄 표시 |

예배 종류는 주일 1·2·3부, 수요 예배, 금요 기도회, 새벽 기도회, 특별 예배입니다. 상태는 준비 중, 준비 완료, 진행 중, 마친 예배입니다.

진행 중인 예배는 삭제할 수 없습니다. **다음 주로 복사**하면 복사본은 다시 준비 중입니다.

## 예배 전 점검

순서 편집 화면에 점검표가 있습니다. **준비된 항목 체크**는 시스템이 판단할 수 있는 항목만 채웁니다.

자동으로 확인하는 필수 항목은 날짜·시간·장소, 순서, 담당, 주보 반영, 성경 구절, 설교 제목과 설교자, 찬송·찬양 연결, 저작권 표시, 가사 없는 기본값, 슬라이드, 배경, 자막 위치, 하루 전 알림, 한 시간 전 알림입니다.

사람이 직접 체크하는 필수 항목은 송출 화면, 음향, 반주, 화면 출력, 안내와 봉헌입니다. 통역 자막은 선택입니다.

이 필수 항목이 모두 체크되기 전에는 예배가 시작되지 않습니다.

## 주보

**준비** 화면에서 붙여 넣은 글, 텍스트, 워드(DOC, DOCX), 한글(HWP 5.0, HWPX), PDF, RTF, ODT, HTML을 가져옵니다. 한글 인식이 있는 환경에서는 사진(JPG, PNG, WEBP)도 읽습니다. 파일은 8MB 이하입니다. 한 주에 적힌 예배를 한꺼번에 준비합니다.

준비 중이거나 준비 완료인 같은 날·같은 종류 예배는 주보 내용으로 바꿉니다. 진행 중이거나 마친 예배는 바꾸지 않습니다. 주보에 적힌 장소를 예배에 넣습니다. 장소가 없으면 본당입니다. 주보의 사람 이름은 직함이나 띄어쓰기만 달라도 명단과 연결되고, 주보만으로 새 사람을 만들지 않습니다.

찬양은 곡명과 번호만 가져옵니다. 가사로 보이는 줄은 저장하지 않습니다. 성경 구절은 가져오고, 본문 전문은 넣지 않습니다.

한글 3.0 단일 파일은 읽지 못합니다. HWPX나 텍스트로 저장한 뒤 올립니다.

## 화면 송출

순서마다 슬라이드가 만들어집니다. 배경은 색 또는 그림(JPG, PNG, WEBP, 5MB 이하)이고, 자막 위치는 아래, 위, 왼쪽, 오른쪽입니다.

조작 앱이 같은 네트워크의 송출 앱으로 지금 두 줄만 직접 보냅니다. 텍스트 파일은 조작 컴퓨터에만 있고, 본문 전체는 서버에 올리지 않습니다. 교회 데이터(주보·사람·설정 동기화 등)는 기존 Firebase 경로를 그대로 쓰며, 자막 송출 경로만 로컬 직접 연결입니다.

찬송·찬양·성가는 기본적으로 제목만 표시합니다. 사용 허가를 확인한 짧은 문구, 사용 가능한 번역을 직접 붙여 넣고 확인한 성경 본문만 화면에 넣을 수 있습니다. 가사, 악보, 성경 본문 전문을 자동으로 넣거나 화면에 내는 기능은 없습니다.

## 알림

설교자와 순서 담당에게 하루 전, 한 시간 전 일정을 만듭니다. **준비** 화면의 알림 목록은 예정, 지금, 보냄으로 나뉩니다. 브라우저 알림은 그 화면에서 이 브라우저의 알림을 허용한 뒤에만 뜹니다. 마친 예배의 알림은 새로 만들지 않습니다.

문자 발송은 없습니다. 명단에 전화번호가 있으면 준비 화면의 알림 옆에 보여 줍니다. 쉬는 사람은 새 순서의 선택 목록에 나오지 않습니다.
